# Implementation Plan: Sistema de Ventas y Caja

**Branch**: `006-ventas-caja` | **Date**: 2026-05-24 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/006-ventas-caja/spec.md`

## Summary

Expand the existing `ventas` hexagonal module with 7 new aggregates: PuntoDeVenta, TurnoDeAtencion, AperturaCierreDeCaja, Venta, Pedido, Gastos, and ReporteConsolidado. All Prisma models already exist in `50-ventas.prisma` — no schema migrations required. Stock decrement on venta confirmation follows the same `$transaction` pattern as Feature 005's `confirmar-compra`. Consolidated report merges `Venta` (ventas schema) + `AtencionPago` (consultorio schema) at the application layer. Public portal orders (`Pedido`) can be converted to `Venta` by staff.

## Technical Context

**Language/Version**: TypeScript strict, Node.js 20+  
**Primary Dependencies**: Hono (REST), Prisma 7 (`@@schema("ventas")`), Socket.IO, Zod, Vitest  
**Storage**: PostgreSQL — schemas `ventas`, `catalogo` (ProductoVariante/ProductoInsumo), `almacen` (Insumo/MovimientoAlmacen), `consultorio` (AtencionMedica/AtencionPago for report)  
**Testing**: Vitest + fake in-memory repositories (no DB)  
**Target Platform**: Node.js server (Render)  
**Project Type**: REST web service — hexagonal module extension within monolith  
**Performance Goals**: Venta list < 2s for 50k records (SC-006); consolidated report < 5s for 3 months / 10k records (SC-005)  
**Constraints**: All queries tenant-scoped (Art. III); stock update atomic in `$transaction` (SC-003); no cross-module port coupling at runtime; no Prisma migration (working agreement)

## Key Implementation Details

### Stock Decrement on confirmarVenta (FR-014, FR-015)

Inside `VentaPrismaRepository.confirmar()` — single `$transaction`:
```
for each VentaDetalle:
  1. if variante.inventarioActivado:
     - ProductoVariante.cantidadStock -= detalle.cantidad
     - create MovimientoInventario { tipo: SALIDA, referenciaId: ventaId }
  2. query ProductoInsumo where productoId=detalle.productoId
     for each insumo:
     - Insumo.cantidadStock -= (detalle.cantidad × insumo.cantidad)
     - create MovimientoAlmacen { tipo: SALIDA, referenciaId: ventaId }
3. update Venta.estadoPago (mark as confirmed)
4. if tipoPago=EFECTIVO: AperturaCierreDeCaja.montoVentas += totalVenta
return { venta, advertencias }
```

### Consolidated Report (FR-027)

`ReportePrismaRepository.getConsolidado(tenantId, filters)`:
```
parallel:
  query1 = Venta where tenantId + dateRange + optional filters → map to ReporteIngreso(fuente="VENTA")
  query2 = AtencionMedica+AtencionPago where tenantId + dateRange (only if tenant.esConsultorio) → map to ReporteIngreso(fuente="CONSULTORIO")
merge + sort by fecha desc
paginate in memory (for reasonably sized datasets)
return { data, meta }
```

### AperturaCierreDeCaja Uniqueness

Application pre-check: `findFirst({ where: { tenantId, puntoVentaId, turnoId, tenantMemberId, fecha: dayStart..dayEnd } })` before create. DB unique constraint as final guard.

### Montoal Arqueo Calculation (at close)

```
efectivoEsperado = montoInicialCaja + montoIngresos - montoEgresos + montoVentas
diferencia = montoArqueoCaja - efectivoEsperado
```

`montoInicialCaja` is stored as the first `IngresosCaja` with motivo="Apertura" created atomically at `abrir-caja`.
