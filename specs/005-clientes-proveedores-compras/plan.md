# Implementation Plan: Gestión de Clientes, Proveedores y Compras

**Branch**: `005-clientes-proveedores-compras` | **Date**: 2026-05-23 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/005-clientes-proveedores-compras/spec.md`

## Summary

Create the `ventas` hexagonal module with full CRUD for `Cliente` and `Proveedor`, plus `Compra` management (create in PENDIENTE, edit, confirm with atomic stock update). All entities already exist in `prisma/50-ventas.prisma`; only one schema change needed (add `CONFIRMADA` to `Estado` enum). Real-time notifications via `IVentasNotificador` pattern (NullImpl → SocketImpl).

## Technical Context

**Language/Version**: TypeScript strict, Node.js 20+
**Primary Dependencies**: Hono (REST), Prisma 7 (`@@schema("ventas")`), Socket.IO, Zod, Vitest
**Storage**: PostgreSQL — schema `ventas` (50-ventas.prisma), partial `almacen` (for stock update on confirmar)
**Testing**: Vitest + fake in-memory repositories
**Target Platform**: Node.js server (Render)
**Project Type**: REST web service — hexagonal module within monolith
**Performance Goals**: List queries < 1s for up to 10k tenant records (SC-002)
**Constraints**: All queries tenant-scoped (Artículo III), stock update atomic (SC-003), no cross-module port coupling at runtime
**Scale/Scope**: ~5 use cases per aggregate (Cliente, Proveedor, Compra) + real-time events

### IVentasNotificador Events

```typescript
interface IVentasNotificador {
  clienteCreado(tenantId: string, payload: ClienteCreadoPayload): void
  clienteActualizado(tenantId: string, payload: ClienteActualizadoPayload): void
  proveedorCreado(tenantId: string, payload: ProveedorCreadoPayload): void
  proveedorActualizado(tenantId: string, payload: ProveedorActualizadoPayload): void
  compraCreadа(tenantId: string, payload: CompraCreadaPayload): void
  compraActualizada(tenantId: string, payload: CompraActualizadaPayload): void
  compraConfirmada(tenantId: string, payload: CompraConfirmadaPayload): void
}
```

Socket.IO events: `ventas:cliente:creado`, `ventas:cliente:actualizado`, `ventas:proveedor:creado`, `ventas:proveedor:actualizado`, `ventas:compra:creada`, `ventas:compra:actualizada`, `ventas:compra:confirmada`

### ConfirmarCompra — Stock Update in $transaction

`ICompraRepository.confirmar(compraId, tenantId)` runs a single `$transaction`:
1. Find compra; throw `CompraNoEncontradaError` if not found
2. Check `estado === PENDIENTE`; throw `CompraYaConfirmadaError` if not
3. For each `CompraDetalle`:
   - If `varianteId` set: fetch `ProductoVariante` from same DB
   - If `inventarioActivado=true`: increment `cantidadStock += cantidad`, create `MovimientoInventario { tipo: ENTRADA, varianteId, cantidad, stockAntes, stockDespues, createdById }`
   - If `inventarioActivado=false`: push to `advertencias[]`, skip stock update
4. Update `Compra.estado = CONFIRMADA`
5. Return `{ compra, advertencias }`

Post-transaction: use case emits `compraConfirmada` via `IVentasNotificador`.

### Query Params

All list use cases use `makeQueryParamsSchema(filterables, orderables)` from `src/core/query-params.ts`.

| Resource | Filterables | Orderables |
|----------|-------------|------------|
| Cliente | nombre, email, estado | nombre, createdAt |
| Proveedor | nombre, nit, estado | nombre, createdAt |
| Compra | estado, proveedorId | fecha, createdAt |
